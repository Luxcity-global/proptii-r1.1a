# **V2.1: Social Media Asset Creation - The CrewAI-First MVP PRD**

**_A User-Centric Blueprint with Agentic AI at the Core_**

## **1\. Executive Summary**

This document specifies the requirements for the Social Media Assets Creation module using a **CrewAI-first architecture** with a **product-led implementation strategy**. The core mission is to deliver immediate, tangible value to UK Property Marketing Professionals by focusing development on the most critical user workflow first: the "magic moment" of effortless, compliant, AI-driven asset creation.

We will build a complete, scalable tool using **CrewAI's open-source agentic framework** from day one, integrating with a Fabric.js canvas and an automated **UK property advertising compliance validator**. The implementation follows a hybrid approach that builds incrementally on the existing foundation while establishing CrewAI as the intelligence backbone from the start. This approach leverages the cost benefits of open-source AI while ensuring we build a product that users truly love.

## **2\. Vision & Strategy**

### **Vision Statement**

To transform UK property marketing by providing an **agentic AI platform** that is compliance-focused, enabling estate agents and marketers to create professional, engaging content in **under 5 minutes per asset**, while maintaining full UK property advertising compliance.

### **Product Strategy: The "Magic Moment" First**

Our strategy is to prioritize the user's core workflow over a comprehensive feature list. We will build in the following order to maximize value and learning at each step:

1. **Create:** Deliver the core AI generation experience first.
2. **Distribute:** Enable users to get their creations out into the world.
3. **Collaborate & Scale:** Build features for team efficiency and power users.
4. **Polish & Expand:** Round out the feature set based on real user feedback.

## **3\. Target State & Core Features**

The end state is the same as the ambitious "V2" plan, but the journey is phased to deliver value faster.

- **V2.1 MVP (End of Phase 2 \- Week 5):** A user can select a property, trigger an AI crew to generate a high-quality, compliant asset, and publish it directly to their social media accounts. The core value loop is complete.
- **V2.1 Complete (End of Phase 4 \- Week 8):** The MVP is enhanced with team templating, advanced scheduling, a full suite of canvas tools, and performance optimizations, resulting in the complete application envisioned in the Figma design.

## **4\. Implementation Strategy & Timeline (Product-Led)**

This plan re-sequences the V2 architecture into a workflow-centric roadmap.

### **Phase 1: The "Magic Moment" Core (Weeks 1-3)**

- **Goal:** A user can select a property, click "Generate with AI," and have a _single_, high-quality, compliant asset generated and placed on the canvas.
- **Definition of Done:** The complete CrewAI agentic workflow is operational on Azure. A minimal canvas UI can trigger the workflow via Azure Service Bus and receive the result. The core technical risks are fully retired.

### **Phase 2: The Distribution Workflow (Weeks 4-5)**

- **Goal:** The user can get their creation out of the system.
- **Definition of Done:** Secure social account connections are functional. The "Publish Now" and "Export" buttons are live, using an asynchronous worker to process the jobs. The user can complete the entire journey from creation to distribution.

### **Phase 3: The Team Efficiency Loop (Weeks 6-7)**

- **Goal:** Make the tool valuable for teams, not just individuals.
- **Definition of Done:** The "Save as Template" feature is live, allowing users to share designs with their team. The "Assets" tray is functional for loading past work. The "Layers" panel and other advanced canvas tools are built out based on early user feedback.

### **Phase 4: Scale & Polish (Week 8\)**

- **Goal:** Round out the feature set and prepare for a wider launch.
- **Definition of Done:** The full scheduling UI with a calendar view is complete. All remaining tool tray functionality is implemented. The application is fully hardened, tested, and ready for a full-scale marketing launch.

## **5\. Technical Architecture**

The technical architecture remains the same as the superior "V2" plan, as it provides the necessary foundation for this product-led approach.

- **Cloud Platform:** Microsoft Azure
- **Agentic AI Service:** CrewAI on Azure Container Apps
- **Messaging (MCP):** Azure Service Bus
- **Web Services:** NestJS on Azure App Service
- **Database & Storage:** Azure PostgreSQL, Redis, and Blob Storage

The key is that this robust architecture is built iteratively, with each service being developed and deployed as needed by the product-led roadmap.

## **7\. UK Compliance Requirements**

The automated, agent-driven compliance engine is part of the **Phase 1** build, establishing it as a non-negotiable cornerstone of the product from day one. It checks for:

- **ASA Mandatory Information**: Price, Tenure, Council Tax Band, EPC Rating.
- **Prohibited Content**: Discriminatory language.

## **8\. Quality Assurance Framework**

The QA strategy is adapted for the product-led approach:

- **Phase 1-2**: Heavy focus on **integration testing** to validate the asynchronous message-passing between services and the quality of the AI output.
- **Phase 3-4**: Shift focus to **end-to-end testing** (Playwright) and formal **User Acceptance Testing (UAT)** with early adopters to refine the workflow and UI.

## **9\. Risk Management**

This product-led plan inherently mitigates the biggest project risks early.

| Risk                                    | Likelihood | Impact   | Mitigation Strategy (Now Part of the Plan)                                                                                                                                                                                                     |
| --------------------------------------- | ---------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agentic AI Fails to Deliver Quality** | Medium     | Critical | **Mitigated in Week 2\.** By building the entire CrewAI workflow first, we can immediately test and validate the quality of the AI output. If it's not good enough, we can pivot our AI strategy without having wasted time on other features. |
| **Users Don't Value the Core Feature**  | Low        | High     | **Mitigated in Week 3\.** By delivering a functional MVP, we can gather real user feedback on the core "magic moment" and validate our primary hypothesis before committing to the full 8-week plan.                                           |
| **Technical Complexity Delays Launch**  | Medium     | High     | **Mitigated by Phased Rollout.** Each phase delivers a complete, testable piece of the product. This reduces the pressure of a single "big bang" launch and allows for more predictable progress.                                              |

## **10\. Success Metrics**

Success metrics are tied to the phased rollout.

- **Phase 1 Success**: The dev team can successfully run the end-to-end agentic workflow and see a compliant asset generated. Technical risk is eliminated.
- **Phase 2 Success**: Early users can successfully publish an AI-generated asset to a social media account. The core value loop is validated.
- **Post-Launch Success (3 Months)**:
  - **Asset Creation Time**: Reduced by **75%**.
  - **User Adoption**: \> 60% of users trigger an AI crew task.
  - **Engagement Uplift**: Average **40%** increase in social media engagement.
