# **Phase 2 Implementation Plan: Core Value Features & Distribution**

**Duration:** 4 Weeks (Project Weeks 5-8)  
**Focus:** Enable the complete user workflow from creation to distribution, building on the CrewAI foundation and professional canvas from Phase 1.  
**End Goal:** Users can generate, optimize, and publish AI-created content across multiple platforms. Basic scheduling and team sharing capabilities complete the core value loop.

**Key Success Criteria:**

- Complete workflow from property to published asset in <5 minutes
- AI-generated content achieves measurable quality improvements
- Multi-platform publishing operational (Facebook, Instagram, LinkedIn, Twitter)
- Basic team collaboration features functional

### **1\. Executive Summary & Vision (Phase 2\)**

This document outlines the tactical execution for weeks 5-8, building directly upon the CrewAI foundation and professional canvas from Phase 1\. With the core creation tools in place, this phase is dedicated to building the "last mile"—connecting our users' creations to their audience and introducing features that drive team efficiency. We will implement direct social media publishing, a foundational scheduling system, and the first iteration of team collaboration features, addressing the critical gaps in the current codebase.

**Phase 2 Vision:** To transform the editor from a standalone creation tool into an integrated marketing workflow engine. Success in this phase is defined by a user successfully completing the entire journey from property selection to a live social media post, all within our platform, in under five minutes.

### **3\. Target State & Core Features (Phase 2\)**

Upon completion of Phase 2, the following features will be fully implemented and "Done":

- **Direct Social Media Publishing:**
  - Secure OAuth 2.0 connections for Facebook Pages and Instagram Business accounts.
  - A backend publishing service capable of posting images and text.
- **Asynchronous Job Queue:** A robust system (e.g., using Redis or a dedicated database table) to manage publishing and scheduling jobs without blocking the UI.
- **Basic Scheduling System:** Users can schedule a post for a future date/time. A backend CRON job processes the schedule.
- **Team Templating (V1):** Users can save a canvas design as a named template, which then appears in the "Templates" tray for others in their workspace.
- **Optimized AI Content Generation:** The CrewAI agents are refined with platform-specific knowledge, allowing users to generate content optimized for Instagram's visual focus vs. LinkedIn's professional tone.

  ### **4\. Technical Architecture (Phase 2\)**

This phase introduces new services and refines existing ones within the Express/Node.js backend.

#### **Backend (Express/Node.js)**

- **New `PublishingService`:**
  - **Responsibilities:** Manages OAuth tokens for social platforms, constructs API requests for each platform, and adds jobs to a queue.
  - **Tech:** Will use libraries like `passport.js` for OAuth and `axios` for API calls to the Facebook Graph API.
- **New `SchedulerService`:**
  - **Responsibilities:** A CRON job (using `node-cron`) will run every minute. It will query the `scheduled_posts` table for jobs due to be published.
  - **Logic:** When a job's time has come, the `SchedulerService` will pass it to the `PublishingService` to be queued for immediate posting.
- **Job Queue:** To handle asynchronous tasks, a simple but effective job queue will be implemented using a dedicated PostgreSQL table (`publishing_jobs`). A worker process will poll this table to execute jobs.

  #### **API Specification (Phase 2\)**

```
// POST /api/publishing/connect/facebook
// Initiates OAuth flow for Facebook/Instagram

// POST /api/publishing/publish-now
// Body: { canvasData: JSON; caption: string; platforms: ['instagram', 'facebook']; }
// Response: 202 Accepted { jobId: 'uuid' }

// POST /api/publishing/schedule
// Body: { canvasData: JSON; caption: string; platforms: [...]; scheduledAt: 'ISO_STRING'; }
// Response: 202 Accepted { scheduleId: 'uuid' }

// POST /api/templates
// Body: { name: string; canvasData: JSON; }
// Response: 201 Created { templateId: 'uuid', name: 'Modern Minimal' }

```

#### **Database Schema (Phase 2 Additions)**

```
-- Stores user connections to social platforms
CREATE TABLE social_connections (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES users(id),
    platform VARCHAR(50) NOT NULL,
    access_token TEXT NOT NULL,
    refresh_token TEXT,
    expires_at TIMESTAMP,
    platform_user_id VARCHAR(255)
);

-- Stores scheduled posts
CREATE TABLE scheduled_posts (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES users(id),
    canvas_project_id UUID REFERENCES canvas_projects(id),
    caption TEXT,
    platforms JSONB,
    scheduled_at TIMESTAMP WITH TIME ZONE NOT NULL,
    status VARCHAR(20) DEFAULT 'pending' -- pending, processing, complete, failed
);

```

### **5\. Implementation Strategy & Detailed Sprint Breakdown (Phase 2\)**

This 4-week phase is broken into eight focused sub-sprints for systematic implementation.

#### **Sprint 2.1a: OAuth & Social Platform Foundation (Week 5, Days 1-3\)**

**Goal:** Establish secure social media platform connections  
**Tasks:**

1. **OAuth 2.0 Implementation**

   - Set up Facebook/Instagram Business API credentials and permissions
   - Implement secure OAuth flow with PKCE for enhanced security
   - Create token storage and refresh mechanisms
   - Add LinkedIn and Twitter OAuth integration

2. **Social Platform API Integration**
   - Integrate Facebook Graph API for Pages and Instagram Business
   - Add LinkedIn API for company page posting
   - Implement Twitter API v2 for tweet publishing
   - Create unified social platform abstraction layer

**Deliverables:** Secure OAuth flows for all platforms, token management system

#### **Sprint 2.1b: Publishing Service Architecture (Week 5, Days 4-7\)**

**Goal:** Build robust backend publishing infrastructure  
**Tasks:**

1. **PublishingService Development**

   - Create platform-agnostic publishing service
   - Implement image upload and processing for each platform
   - Add content formatting and optimization per platform
   - Build retry logic and error handling

2. **Job Queue Implementation**
   - Set up Redis-based job queue for asynchronous processing
   - Create job priority and scheduling mechanisms
   - Implement job status tracking and reporting
   - Add dead letter queue for failed jobs

**Deliverables:** Complete publishing backend, job queue system

#### **Sprint 2.2a: Publishing UI & Account Management (Week 6, Days 1-3\)**

**Goal:** Create user-friendly social account management interface  
**Tasks:**

1. **Account Connection UI**

   - Build social account connection modal/page
   - Implement account status display and management
   - Create account disconnection and reconnection flows
   - Add platform-specific connection instructions

2. **Publishing Options Panel**
   - Enhance existing publishing panel to match Figma design
   - Add platform selection with preview capabilities
   - Implement caption editing with platform-specific character limits
   - Create publishing queue status display

**Deliverables:** Complete account management UI, enhanced publishing panel

#### **Sprint 2.2b: AI Content Optimization (Week 6, Days 4-7\)**

**Goal:** Enhance CrewAI agents with platform-specific optimization  
**Tasks:**

1. **Platform-Aware Content Generation**

   - Update ContentGenerationAgent with platform-specific prompts
   - Add Instagram vs LinkedIn vs Facebook content optimization
   - Implement hashtag generation and optimization
   - Create call-to-action optimization per platform

2. **Content Optimization Workflow**
   - Add "Optimize for Platform" button to UI
   - Implement A/B testing content generation
   - Create content performance prediction
   - Add real-time content analysis and suggestions

**Deliverables:** Enhanced AI agents, platform-specific optimization features

#### **Sprint 2.3a: Scheduling Infrastructure (Week 7, Days 1-3\)**

**Goal:** Build comprehensive scheduling system  
**Tasks:**

1. **Scheduling Backend**

   - Implement node-cron based scheduler service
   - Create scheduled post management system
   - Add timezone handling and daylight saving support
   - Build scheduling conflict detection and resolution

2. **Advanced Scheduling Features**
   - Implement recurring post capabilities
   - Add optimal posting time suggestions using AI
   - Create bulk scheduling operations
   - Build scheduling analytics and reporting

**Deliverables:** Complete scheduling backend, advanced scheduling features

#### **Sprint 2.3b: Team Templating System (Week 7, Days 4-7\)**

**Goal:** Enable team collaboration through template sharing  
**Tasks:**

1. **Template Management Backend**

   - Create template storage and versioning system
   - Implement team workspace template sharing
   - Add template categorization and tagging
   - Build template permissions and access control

2. **Template UI Integration**
   - Enhance Templates tool tray with team templates section
   - Add "Save as Template" functionality with metadata
   - Implement template preview and usage tracking
   - Create template marketplace for popular designs

**Deliverables:** Complete team templating system, enhanced Templates tray

#### **Sprint 2.4a: Analytics Foundation (Week 8, Days 1-3\)**

**Goal:** Establish analytics infrastructure for performance tracking  
**Tasks:**

1. **Analytics Data Collection**

   - Implement social platform metrics fetching
   - Create analytics data storage schema
   - Build automated data collection workers
   - Add data validation and quality checks

2. **Basic Analytics Dashboard**
   - Create simple analytics dashboard UI
   - Implement key metrics visualization
   - Add post performance comparison features
   - Build export capabilities for analytics data

**Deliverables:** Analytics infrastructure, basic dashboard

#### **Sprint 2.4b: End-to-End Polish & Testing (Week 8, Days 4-7\)**

**Goal:** Complete workflow integration and comprehensive testing  
**Tasks:**

1. **Workflow Integration Testing**

   - Test complete user journey from creation to analytics

   - Performance test publishing and scheduling under load

2. **User Experience Polish**

### **6\. UK Compliance Requirements**

The `ComplianceValidationAgent`'s check is now a mandatory gateway. The `PublishingService` must reject any job where the asset has not received a passing grade from the compliance agent.

### **7\. Quality Assurance Framework**

The QA focus shifts to **external integration testing**. This requires setting up developer accounts on Facebook/Instagram and writing automated tests that can verify a post was successfully created.

### **8\. Risk Management**

| Risk                         | Likelihood | Impact | Mitigation Strategy                                                                                                                                                        |
| :--------------------------- | :--------- | :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Social Media API Changes** | High       | High   | Abstract the publishing logic behind a generic interface. If the Instagram API changes, we only need to update the "Instagram adapter," not the entire publishing service. |
| **Invalid Access Tokens**    | Medium     | High   | Implement robust error handling and a refresh token flow. The UI must clearly prompt the user to re-authenticate if a connection fails.                                    |
| **Scheduler Failure**        | Low        | High   | Implement comprehensive logging and a retry mechanism for the CRON job. Add monitoring to alert the team if the scheduler fails to run.                                    |
