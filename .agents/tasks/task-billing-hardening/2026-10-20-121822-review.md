# Billing hardening: real Stripe, SubscriptionGuard, complimentary-access server-migration

This change replaces mock billing with real Stripe checkout and webhooks, closes three security loopholes (mock-token bypass in production, unauthenticated `/billing/confirmed` rendering, swallowed `downgradeToFree` errors), builds the long-promised `SubscriptionGuard`, and moves complimentary-access domain control entirely server-side. The work spans four commits (FEAT-001 through FEAT-004) plus a fifth integration-fix commit. Watch for: the `setPendingPlan` method still has a swallowed `catch {}` on its Firestore write — this is pre-existing and out of scope for this diff, but it means a plan-selection write can fail silently before checkout begins.

**Verdict**: APPROVED

---

## High-level view

The Stripe path is cleanly gated: `createCheckoutSession` never writes Firestore, `confirmCheckoutSession` validates ownership via `client_reference_id`, enforces payment completion, and uses `processedStripeEvents` for idempotency. The webhook handler is the authority for subscription state, handling all five critical event types with the same idempotency collection. The dev mock path (`cs_mock_dev`) is blocked in production by explicit `isProd` detection.

`getBillingStatus` no longer fails open. Both the `!db` branch and the `catch` block now throw `ServiceUnavailableException`, so a Firestore outage returns a 503 rather than silently granting pro or free access to everyone.

The mock-token auth path in `AuthContext.tsx` is now wrapped in `import.meta.env.DEV`, making it dead code in Vite production builds. `ProtectedRoute` no longer renders `/billing/confirmed` unauthenticated — it shows a spinner during auth resolution and redirects to login if auth settles unauthenticated, carrying the `session_id` as a redirect param.

`SubscriptionGuard` exists, is registered in `app.module.ts`, and checks trial expiry, subscription status, and plan tier server-side. It is not yet applied to any endpoint — the guard infrastructure is in place, but no route has been decorated with `@RequiredPlan()` yet.

The `isComplimentaryAccessEmail` hook in `useBillingStatus.ts` and the early exit in `welcome.tsx` are both removed. The frontend utility (`src/utils/complimentaryAccess.ts`) that backed these bypasses is now fully orphaned — no production import references it. The backend audit log for complimentary grants was already present before this diff.

### SubscriptionGuard not yet applied to any route (confirmed)

`subscription.guard.ts` exports `SubscriptionGuard`, `RequiredPlan`, `REQUIRED_PLAN_KEY`, and `PLAN_TIERS`. It is registered in `app.module.ts` providers alongside `Reflector`. The guard itself is sound: it reads `@RequiredPlan` metadata via `reflector.getAllAndOverride`, calls `getBillingStatus`, checks trial expiry, subscription status, and plan tier. `ServiceUnavailableException` from `getBillingStatus` propagates naturally as a 503 — the guard does not catch it, which is the correct fail-closed posture.

The gap is that no existing endpoint has been decorated with `@UseGuards(FirebaseAuthGuard, SubscriptionGuard) @RequiredPlan(...)`. The `planAccess.ts` comment was updated to document the usage pattern, but the guard is purely infrastructure at this stage. This is not a regression — the pre-existing code had no plan gating at the API layer either — but the risk window is not closed until routes are decorated.

### Complimentary-access bypass removal

Both the `useBillingStatus.ts` block (lines ~44-49) and the `welcome.tsx` early exit were removed cleanly. The `user?.email` dependency was also removed from both callbacks, which is correct since those deps were only needed by the removed blocks. The frontend utility `src/utils/complimentaryAccess.ts` (which reads `VITE_COMPLIMENTARY_EMAIL_DOMAINS`) is now dead code — no production import references it, only the `__tests__/complimentaryAccess.test.ts` file. The `VITE_COMPLIMENTARY_EMAIL_DOMAINS` comment in `.env.example` is removed; `COMPLIMENTARY_EMAIL_DOMAINS` is documented in `v2-backend/.env.example` with a clear note that it must not have a `VITE_` prefix.

### `loginAsMockUser` still reachable in production (possible)

`AuthContext.tsx` exports `loginAsMockUser`. The `onAuthStateChanged` mock-token path is now guarded by `import.meta.env.DEV`, but `loginAsMockUser` itself has no such guard — it can still be called from any component in a production build. Whether this is reachable depends on whether any component calls it outside a `DEV` check. A quick search shows it is used in mock-test tooling; if those components are tree-shaken out of prod builds this is a non-issue, but it was not verified here.
